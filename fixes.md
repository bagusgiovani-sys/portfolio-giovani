## ARCHITECTURE ISSUES

### 19. page.tsx forces full CSR
**File:** `src/app/page.tsx` line 3  
**Detail:** `'use client'` is required only for `useState(showSplash)`. This makes the entire page client-side rendered, losing Next.js SSR/SSG benefits (SEO, TTFB, hydration).  
**Fix:** Move the splash state into a `<SplashGate>` client component that wraps the section list. Remove `'use client'` from page.tsx.

### 20. Dual CSS token systems
**File:** `src/app/globals.css`  
**Detail:** Two token systems coexist:
- `@theme` (lines 8–71): Brand tokens (`--color-brand-*`, `--color-primary-*`)
- `:root` (lines 165–198): shadcn OKLCh tokens (`--background: oklch(…)`)
- `@theme inline` (lines 124–163): Bridges shadcn vars into the `--color-*` namespace

This means `bg-background` resolves to the OKLCh warm-tan value from `:root`, not the `#ffffff` from `@theme`. The two systems define conflicting values for the same semantic tokens.  
**Fix:** Decide on one system. If using brand tokens, remove the `:root` shadcn block. If using shadcn, remove the redundant `@theme` top block.

### 21. Three competing dark mode mechanisms
**File:** `src/app/globals.css` lines 5, 73, 200  
**Detail:** Dark mode is defined via `@custom-variant dark (&:is(.dark *))` (class-based), `@media (prefers-color-scheme: dark)` (system), and `.dark {}` class selector — all three exist simultaneously. No toggle UI exists so only system preference applies, but the `.dark` class overrides never fire.  
**Fix:** Pick one. If there's no manual dark mode toggle, use only `@media (prefers-color-scheme: dark)` and remove the class-based approach.

## ACCESSIBILITY

### 24. cursor:none on map card
**File:** `src/components/sections/AboutSection.tsx` line 591  
**Detail:** `style={{ cursor: "none" }}` removes the cursor entirely on the map card. Users with motor disabilities or keyboard-nav assistive tech rely on visible cursor feedback.  
**Fix:** Use `cursor: crosshair` or `cursor: zoom-in` instead.

### 25. No prefers-reduced-motion support
**File:** `src/app/globals.css`, all section components  
**Detail:** Ticker animations (`animate-ticker-mobile`, `animate-ticker-pc`, `animate-ticker-reverse`) and continuous Framer Motion loops (`repeat: Infinity`) run with no reduced-motion fallback. This can cause issues for users with vestibular disorders.  
**Fix:** Add `@media (prefers-reduced-motion: reduce) { .animate-ticker-* { animation: none; } }` to globals.css.

### 26. Star ratings have no screen reader text
**File:** `src/components/sections/HeroSection.tsx` line 87, `src/components/sections/TestimonialSection.tsx` line 79  
**Detail:** Stars rendered as icon-only elements with no `aria-label` or `<span className="sr-only">` text.  
**Fix:** Add `<span className="sr-only">5 out of 5 stars</span>` adjacent to the stars.

### 27. Form error modal has no ARIA role
**File:** `src/components/sections/ContactSection.tsx`  
**Detail:** Success/error modal appears dynamically but has no `role="alertdialog"` or `aria-live` — screen readers won't announce it.  
**Fix:** Add `role="alertdialog"` and `aria-modal="true"` to the modal div.
